# QuietNeeds v2: An answer for every request

A message can tell an organizer what someone needs. QuietNeeds can give each practical request a clear status before the event. Participants can share the adjustment they need without explaining why, and organizers can see which requests still need a decision.

## The release idea

Put **Needs a decision** above the organizer’s agenda editor and **What changed for you** above the participant’s published agenda. Publish the agenda and private request outcomes together.

| Approved request | Organizer action | What the participant sees |
| --- | --- | --- |
| A seated alternative to the photo walk | Link the request to the 10:00 seated photo exercise | The revised activity and two actions: **Works for me** and **Still need help** |
| Step-free entrance | Mark **Still checking** while the venue confirms access | **Still checking**. The entrance is unconfirmed. |
| A printed copy of the worksheet | Mark **Can’t provide** if the organizer cannot supply one | **Can’t provide**, so the participant can make an informed decision |

The organizer sees individual responses on the current agenda. An answer about seating cannot cover an unanswered entrance request. If an approved card is replaced or withdrawn, its previous outcomes and responses stop appearing. A newly published agenda starts with fresh feedback.

## Why an organizer would open it

The event workspace puts approved requests next to the agenda and venue facts. Organizers can see which requests need a decision, connect an answer to a real activity, and find anything that still needs follow-up after publishing. Participants can check what will actually be available before deciding whether they can attend.

## What ships first

Reuse the existing card approval, event workspace, and publishing flow. Use three organizer choices: link a published activity, still checking, or can’t provide. Show only the participant’s own request outcomes. Keep messages and notifications out of this release. The workflow works with manual planning and uses existing AI proposals only when the organizer chooses to review them.

## How to show it in a short demo

Share two fictional requests. Publish an agenda that moves the photo exercise to a seated activity and leaves step-free entry unconfirmed. In the participant view, confirm that the seated activity works. Return to the organizer view and show that the entrance still needs a decision. That is the difference a judge or organizer should be able to see in under a minute.

For a small pilot, measure how many shared requests receive a clear outcome before the event, and how many still require a follow-up message.
